# Категоризация операций (ТЗ-доработка WP-3)

Модуль: `server/src/services/categorizer.service.js` (чистые функции, без БД), словари —
`server/src/config/categories.config.js`. Таксономия — 17 подкатегорий (таблица ТЗ §4).

## Методики и пороги

- Нормализация текста: `normalizeForRules` (utils/text.js) — нижний регистр, `ё → е`,
  удаление номеров документов/дат/сумм, схлопывание пробелов.
- Порядок правил (первое сработавшее): свои средства → возвраты → налоги → зарплата →
  кредиты/лизинг → аренда → комиссии банка → эквайринг → маркетплейсы → поставщики → клиенты → прочее.
- Уверенность: ключевое слово — 0.9; ИНН-правило (п.5) — 0.6; без совпадений — `unknown`/`other_*`, 0.
- ИНН-правило (п.5): контрагент с одним ИНН ≥ 3 раз и ≥ 80 % размеченных операций (conf ≥ 0.9)
  в одной подкатегории → его операции с пустым/нераспознанным назначением получают эту подкатегорию.
- Направление проверяется таксономией: правило не применимо к несовместимому направлению.

## Контроль качества (приёмка ТЗ §4)

- `server/tests/fixtures/categories.gold.csv` — 300 операций ≥ 10 компаний, размеченных вручную
  двумя участниками. Генератор стартовой выборки (seed 42, стратификация 50/50 по направлению):
  `node server/scripts/make-gold.mjs [папка-с-выписками]` (папка по умолчанию `test-data/statements/`).
- `server/tests/categorizer.test.js` падает при: accuracy < 0.90, macro-F1 < 0.85,
  доля unknown + other_in + other_out > 10 %. Без gold-файла тесты пропускаются (см. вывод vitest).

## Ограничения

- Gold-набор ещё не размечен людьми (механика готова); итоговые accuracy/macro-F1 появятся после
  подстановки `categories.gold.csv`.
- Для C001 отсутствуют категории эквайринга/маркетплейса (в выписке нет таких операций) —
  «≥ 8 категорий» достигается на 8 реально представленных.
